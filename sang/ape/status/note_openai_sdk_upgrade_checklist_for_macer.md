## What to read first (the findings that can change a loan run)

1. **Tool failures no longer tell the model what went wrong (openai-agents 0.23.0, first on PyPI as 0.23.1; the 0.19.4 and 0.20.0 steps before it).** `default_tool_error_function` returned `An error occurred while running the tool. Please try again. Error: {error}`; since #5112 it returns the fixed sentence `An error occurred while running the tool. Please try again.` Before that, 0.19.4 redacted invalid tool-argument errors and 0.20.0 redacted JSON-validation errors. So the exposure starts at 0.19.4, not 0.24.0. macer's tools raise plain exceptions whose text coaches the model (`tools/documents.py:103,106` "Unknown document source ...", `tools/repl.py:71,78`), and macer sets no `failure_error_function` (grep: none). Likely.
2. **Non-streaming Responses with status `failed` or `incomplete` now raise `ModelBehaviorError` (openai-agents 0.22.0, breaking).** macer caps output with `max_tokens=macer_max_output_tokens` so that truncation is "a bounded, detectable event" (`agents/__init__.py` `build_model_settings`), and `hooks.py` counts `incomplete_responses` from the response. A truncated response now raises before that path, into the generic `model_behavior_errors` retry bucket (`agents/agent_utils.py:340-351`) instead of the incomplete-output bucket. Likely.
3. **Strict JSON schema conversion got stricter in six releases** (0.17.8, 0.18.3, 0.19.0, 0.19.3, 0.20.0, 0.23.0: bound `$ref` expansion, reject empty `additionalProperties`, reject unsafe ref siblings and excessive recursion depth, normalize typeless objects). macer's output types go through `AgentOutputSchema` (`agents/validated_output.py:108`) and `RawJsonSchemaOutput(strict=True)` (`agents/json_schema_output.py:36`). A schema that converted before can now be rejected with `UserError`, or convert differently. Possible; checkable offline by building every output schema.
4. **Cache-write usage accounting grew new fields** (openai 3.36.0 "30-minute cache-write usage counts", 3.45.0 "12-hour Responses caching and cache-write usage", 3.9.0 "prompt cache diagnostics", 3.6.0 `compute_units`; openai-agents 0.18.1 "support cache-write usage across OpenAI Python versions", 0.20.0 preserve raw usage payloads). `hooks.py:476-501` reads `input_tokens_details.cached_tokens` and `cache_write_tokens` and subtracts both from `input_tokens`. If a response splits writes across a second field, input tokens are overcounted and cost drifts. Possible.
5. **TLS trust store and HTTP client (openai 3.0.0, breaking).** HTTPX2 replaces httpx as the default client; the default trust store moves from certifi to the OS store; `SSL_CERT_FILE` and `SSL_CERT_DIR` are honored when `trust_env=True`; stream consumption is not auto-retried. macer builds plain `AsyncOpenAI(timeout=...)` clients (`agents/__init__.py:148,226`), so the client swap is transparent, but a container image without the system CA bundle, or a TLS-inspecting proxy that macer previously trusted through certifi, can now fail at connect. litellm (embeddings, Claude) still uses certifi, so the two stacks can disagree. Possible.
6. **`litellm.acompletion` interception (`models/anthropic.py:191-216`).** `AnthropicModel` swaps `litellm.acompletion` to inject `cache_control`. If any agents or litellm release routes `LitellmModel` through another entry point (litellm 1.106.0 and 1.108.0 changed the Responses bridge and cache-breakpoint handling), the swap stops applying and Claude cache hits drop to zero silently. Possible; visible as `cached_tokens` on Claude spans.
7. **litellm 1.109.0 stream and error semantics.** A stalled stream now returns `litellm.Timeout` 408 (was 500 `APIConnectionError`) and retries, cooldowns and fallbacks now apply, so litellm-level retries can stack on macer's `RetryingModel` and `AsyncOpenAI` retries. macer's `TransientErrors` matches by status (408 in `STATUS`) and by name `Timeout` (`runtime/retry.py:55-62`), so classification is covered; the attempt count is not. Possible.
8. **max_tokens defaults.** litellm 1.109.0: Claude with no `max_tokens` defaults to the model's limit (128000 for cost-map-missing models; was 4096). macer always sends `max_tokens`, so none for the main path; check any call path that does not (the embedding path has no such parameter).

## httpx, jiter, certifi

- **httpx:** 0.28.1 (2024-12-06) is the latest stable. 0.28.0 removed `proxies=` and `app=` and deprecated string `verify=` and `cert=`. Six `1.0.devN` pre-releases (2025-07 to 2026-08) have no release notes on any page read; CHANGELOG master lists 1.0.0 as unreleased with Python 3.10 as the minimum. Source: `https://github.com/encode/httpx/releases`, `https://github.com/encode/httpx/blob/master/CHANGELOG.md`, `https://pypi.org/project/httpx/`. Macer exposure: none on macer's side directly (it imports httpx only in `runtime/retry.py` for the Knowledge Hub client); openai 3.x no longer installs it, litellm still does.
- **jiter:** 0.11.0 (2025-09-11) partial-mode string handling; 0.17.0 (2026-09-12) "use digit run to determine float or integer decode" (PR title, unverified); defaults on 0.19.0 per PyPI: `allow_inf_nan=True`, `float_mode='float'`. openai 3.x requires `jiter>=0.16.0,<1`. Source: `https://github.com/pydantic/jiter/releases`, `https://pypi.org/project/jiter/`. Macer exposure: possible, low: only affects partial JSON parsing in the openai SDK; macer validates output with Pydantic (which vendors its own parser).
- **certifi and truststore:** not read. openai 3.0.0 stops installing certifi (HX2); litellm and openai-agents 0.25.0 still require it.
