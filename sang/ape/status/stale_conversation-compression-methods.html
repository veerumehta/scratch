Context engineering · reference note

Conversation compression in LLM agents

Method families, a working taxonomy, and citable anchors

Reference note · June 2026 · prepared for work on knowledge graphs and large language models

1Overview

There is no formal ISO- or RFC-style standard for compressing an agent's conversation history. What exists instead is a recognizable set of method families and an emerging 2025–2026 survey literature that imposes a shared taxonomy on them. The most useful framing organizes agent context compression along three orthogonal dimensions rather than as a flat list of techniques: the compression target (what is compressed), the compression mechanism (how it is transformed and retained), and the control policy (who decides when compression is triggered). When citing a "standard," cite the taxonomy — not a single algorithm — because the methods remain, by the survey literature's own account, scattered and only preliminarily synthesized.

A second distinction is load-bearing for any literature review: prompt compression reduces a single static input, whereas conversation compression operates over a multi-turn trajectory whose relevance structure evolves over time. Several widely cited "compression" methods (token pruning, soft-token gisting) are really single-turn input compressors borrowed into the multi-turn setting, and should be labeled as such.

4Framing points for a paper

Cite the taxonomy, not an algorithm

The survey literature is explicit that the methods are scattered across compression targets, transformation mechanisms, and control strategies — spanning pruning, summarization, selective retrieval, and representation-level interventions — and that these efforts remain preliminary and disjointed, without systematic synthesis [1]. A claim of a "standard" should therefore reference the three-axis taxonomy.

Separate prompt compression from conversation compression

Prior surveys on prompt compression treat single-turn reduction of static inputs; conversation compression concerns multi-turn trajectories whose relevance structure evolves over time [1]. LLMLingua and gisting are best classified as single-turn input compressors adapted to the multi-turn case [4], [5].

MemGPT is the standard anchor for the offload family

It frames context management as OS-style virtual memory — paging information between a limited main context (the active window) and external recall and archival storage (a searchable message database and a vector-indexed long-term store) [2]. Most subsequent memory systems position themselves relative to it.

Use LoCoMo for the evaluation section

On long-dialogue QA, long-context models and RAG improve "memory" by roughly 22–66% but still lag humans substantially, especially on temporal reasoning; both also perform poorly on event-graph summarization, suggesting they capture isolated facts without comprehending the broader relational structure [7]. This result is the empirical case for graph-structured memory over flat summarization.

Define fidelity relative to the downstream task

Compression quality is task-dependent, not universal. Production evaluation makes the point concrete: a chat assistant can afford to forget earlier topics, but a coding agent that forgets which files it modified will make conflicting edits [6]. This argues for probe-based evaluation over generic n-gram overlap metrics.
