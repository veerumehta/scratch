Two halves

A library to import, and a service to run on

jazzx_sdk

The SDK, as a library

For a team that owns its own service and wants the platform's building blocks inside it.

  • Knowledge fabric and platform agents
  • Declarative pipelines run by the Conductor
  • Policy, evaluation and feedback

plato

The SDK, hosted

For a consumer that needs a place to run rather than a library to import.

  • Multi-tenant HTTP, addressed by assistant
  • A versioned pack store and Postgres control plane
  • An operator dashboard and a boot contract

Same code underneath: Plato imports the SDK, and the SDK never imports Plato.

Japes SDK and Plato

03

The SDK is what you use when you already have a service shell: jaci is the primary example. Plato is for consumers who would otherwise have to stand up their own service just to host an assistant or a domain workflow. Both run the same SDK code, so behaviour does not fork between them.
