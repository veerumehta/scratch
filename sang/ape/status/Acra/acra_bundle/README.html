Terms

  • Job: a requirement written as prose steps and checks that a person or an LLM follows (a JTBD).
  • Code rule: a Python function over case fields that decides some of a job's checks.
  • Procedure: what is left to the reviewer when no check is computable.
  • A job is code when every check is computable and a rule implements it, code_and_procedure when code decides some checks and a reviewer the rest, procedure or not_computable when no check is computable (the latter names the data it lacks), computable_no_code when a check could be code and nobody wrote it, unassessed when nobody said which checks are computable.

Code without a job

The sheet "Code rules without a job" lists code written from a guideline segment that no job is matched to, plus code not yet matched. It is not expected to be empty or always the same size:

  • Code written from a job always has one: it names the job it implements, one rule per job here, so code from jobs can never exceed the jobs and cannot be an orphan. Jobs outnumber it because a job with no computable check gets no code (the not_computable and procedure rows above).
  • Code written from segments (the cross-check pipeline) has no such guarantee. A rule left without a job means the job list lacks a requirement the segment code enforces, or the code is spurious. Its count tells how complete the job list is, not how good the code is. Segment code also matches jobs the job-written code did not reach, which is why jobs coded can exceed the code written from jobs.
  • Action: write the job (the ledger can propose one from the rule's text) or drop the rule.
