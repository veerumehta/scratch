# Codec evaluator helpers: what std could take

Author: Virendra Mehta <virendra.mehta@jazzx.ai>

Companion to `note_shared_function_library_design_2026-11-18.md`. Read-only survey of kernel-lab's `codec-core/workflows/evaluators/` (115 generated evaluator modules; tests and the loan folder not read) and `code_generator_agents/` (the generator's prompts and runtime). No entry is added; this ranks candidates for the user. Counts are **file counts** from grep over the 115 evaluator modules, not call counts; "defs" means the number of files that define a helper of that name (a name family can overlap). Compared with `std/core` and `rules_lib` 1.2.0 as shipped on `v2.7.6`.

## What the generator is told

`type_coercion_guide.md` hands the generator three helper bodies to paste (`_safe_float`, `_safe_int`, `_safe_date`; each returns None on failure) and a table that says to coerce DECIMAL with `Decimal(str(value))` or `float(value)` and BOOLEAN with `value == True or str(value).upper() == "TRUE"`. `materiality_and_tolerance.md` (rule 4j) fixes the reconciliation tolerances at +/-1.00 dollars and +/-0.125 percent and says to normalize names. `evaluator_generator.md` requires named constants for every threshold and a docstring on every helper. The runtime offers `EvaluatorBase` methods for findings, facts and conditions only: it has no arithmetic, date, text or matching helper, so every evaluator writes its own. That is why 115 modules carry 60 to 100 near-copies of a handful of 5-line functions, each copy drifting a little. The fix is to tell the generator which std function to call, not to add more helper text to the prompt.

## Already in std or `rules_lib` (no new entry; the gap is that the generator is not told)

| Pattern in the evaluators | Files | std or `rules_lib` today | Where the copies disagree |
|---|---|---|---|
| Yes/no coercion (`_is_true`, `_as_bool`, `_to_bool`, `_bool`, `_truth`, `_true`, `_safe_bool`, `_is_false`) | 97 | `rules_lib.flag` (True, False, None; blank is None) | `_is_true` (26 files, 16 bodies) answers False for any other text, so an unstated flag reads as "no"; accepted tokens differ (`T`/`F` in some, not others; `YES`/`Y`/`1` in some, `TRUE` only in 6 files); `flag` also takes `on` and `off`, which no copy does |
| ISO date coercion (`_safe_date`, `_date`) | 58 | `rules_lib.day` | `strptime(str(v)[:10])` (most) versus `fromisoformat(... .replace("Z", "+00:00"))` (a timestamp with an offset keeps its own calendar date); "" returned as None in some and an error path in others |
| Whole months between dates (`_months_between`, 6 files) | 6 | `rules_lib.months_between` (floor, negative allowed) | six bodies, five meanings: floor with day adjustment, unclamped (2); floor, clamped at zero (3); **no day adjustment at all** (`inc_bon`, whose docstring says "one-month minimum" and whose code has none: Jan 31 to Feb 1 is 1) |
| Pay-frequency to monthly (`WEEKLY` 52/12, `BIWEEKLY` 26/12, `SEMIMONTHLY` 2) | 8 | `rules_lib.monthly` | same factors; one file hand-codes if-chains and accepts `TWICEMONTHLY` and `BIWEEKLYPAY` |
| Newest row by date (`_latest_row`) | 11 | `rules_lib.latest` | all 11 compare ISO **strings** (`max` of `str(row.get(col))`), which orders a bare date and a timestamp wrongly and treats None as "" (oldest); `latest` parses |
| Text key for matching (`_clean`, `_token`, `_norm`, `_normalize`) | 93 | `rules_lib.norm` and `same` | `_clean` and `_token` upper-case and drop every non-alphanumeric, so "2-4 unit" and "24 unit" collide (`norm` keeps a digit gap); None becomes "" and so equals a blank |
| Same person or organization (`_names_equivalent`, `_names_match`, `_entities_equivalent`) | 21 | `rules_lib.same_person`, `same_org` | 21 files, one body each; at least one accepts substring containment ("SMITH" in "SMITHFIELD HOLDINGS" matches), several then call the text analyzer (an LLM) as a fallback, which is not a pure function and stays out of std |
| Tolerance compare (`abs(a - b) <= TOLERANCE`) | 59 | `rules_lib.close(a, b, tolerance, relative)` | the constants are the generator's (1.00 and 0.125 percent); `Decimal("1.00")` appears in 56 files, `Decimal("0.125")` in 11; whether 0.125 percent is of the left or the right value is not stated anywhere |
| Percent as a number (`* 100`) | 31 | `rules_lib.percent(value, unit)` | scale: some formatters multiply a fraction by 100, some print a value already in percent |

## Candidate new entries, ranked

Ranking is by files that re-implement the pattern, then by how many disagreeing meanings the survey found (a disagreement is the reason to centralize, not only the count). Every entry follows the admission rules (named and typed, pure, Decimal-safe, declared unknown policy, 3 goldens, a version, a summary). Namespace `core` (SDK side) unless noted.

1. **`to_decimal(value)`** -> Decimal or None. 71 files (`_safe_decimal` 45, `_decimal` 26). Unknown policy: propagate (None). Accepts int, float (read as its printed text), Decimal, and numeric text with an optional sign; refuses a bool, a blank, NaN and the infinities. Goldens: `"1250.50"` -> `Decimal("1250.50")`; `True` -> None; `"NaN"` -> None. Disagreements: 17 distinct bodies: blank "" handled (12 files of the largest group) or left to the error path; bool refused (at least 11 files) or not; `$` and `,` stripped (4 files in the groups read). **Only 1 file of 115 checks for NaN or infinity**, and `Decimal("NaN")` parses, so the first comparison raises `InvalidOperation` inside the evaluator; this is the strongest reason to take it. Money text is its own name: **`money_to_decimal(value)`** (strips `$`, commas and spaces; `(1,200.00)` is -1200.00; same policy, 3 goldens `"$1,250.50"`, `"(1,200.00)"`, `"abc"`), used where the extractor returns formatted text.
2. **`to_int(value)`** -> int or None. 66 files (`_safe_int` 53, `_integer` 13). Propagate. Whole numbers only: `3`, `3.0` and `"3"` give 3; `3.7`, `"3.7"` and a bool give None. Goldens: `"12"` -> 12; `3.7` -> None; `True` -> None. Disagreement: 11 bodies, and the common one is `int(value)`, which truncates 3.7 to 3 silently and turns True into 1 (bool refused in 9 files only); `int("3.0")` raises and returns None in the same helper, so the same number gets two answers by type.
3. **`same_address(a, b)`** -> True, False or None. 10 files (`_normalize_address` 5, `_addresses_equivalent` 5, `_format_address` 4); 5 distinct normalizations. Unknown: None when either side is blank (the copies return False with the reason "missing", which reads a gap as a mismatch). Compares street, unit, city, state and ZIP5 only where both sides state them, after street-suffix, directional and unit-designator normalization. Goldens: `"12 Oak Street"` vs `"12 OAK ST."` -> True; `"12 Oak St Apt 4"` vs `"12 Oak St Apt 5"` -> False; `""` vs `"12 Oak St"` -> None. Disagreement: the suffix table has 4 entries in one file and 9 in another, and one compares only the street line while another compares ZIP and state too, so the same pair matches in one evaluator and not in the next. Needs the packs session to say which components a policy compares.
4. **`last_four(value)`** -> text or None. 7 files. Propagate (None for blank; whether fewer than four characters is None or the short text is for packs to decide). Variants, each its own name: `last_four_digits` (digits only: `"xxxx-1234"` -> `"1234"`) and `last_four_chars` (letters and digits, for an account number that carries letters; one copy also prefers an explicit `account_last4` column, which is a row rule, not std). Goldens for the digits form: `"****1234"` -> `"1234"`; `"12"` -> None; `None` -> None.
5. **`roman_numeral(value)`** -> int 1 to 3999 or None. 4 files. Propagate. Validates the numeral (the four copies accept `"IIII"` or `"IC"` or return 0 for text that is not a numeral, and one upper-cases its input and one does not). Goldens: `"IV"` -> 4; `"iv"` -> 4; `"IIII"` -> None. Used for flood-zone and size categories; low value but pure and tiny.
6. **`months_elapsed(start, end)`** -> int or None: `max(0, months_between)`. 3 files clamp after the day adjustment (`crd_derg`, `inc_mil`, `inc_oth`), a fourth clamps with no adjustment (`inc_bon`), and 2 do not clamp (`crd_bas`, `inc_ret`). Own name because `months_between` may be negative and a policy lookback must not be. Goldens: Jan 15 to Mar 14 -> 1; end before start -> 0; None -> None. **Separately, `calendar_months_between(start, end)`** (month-number difference, no day adjustment: Jan 31 to Feb 1 is 1), only if packs confirms a policy wants it, because the one file that implements it describes it as a whole-month count and is probably wrong; do not add it on the strength of that file.
7. **Display text, not logic: `money_text(value, places=2)` and `percent_text(value, scale)`**. 36 files define a money formatter (`_money`, `_money_or_na`, `_display`; 19 distinct bodies) and 8 a percent formatter. They disagree on the missing value (`"N/A"` versus a raise), cents versus whole dollars, and **scale** (one multiplies a fraction by 100, one prints a value already in percent). Worth one entry each only because the strings land in condition text a person reads; unknown policy: `"N/A"`. Rank last: no verdict changes.
8. **`income_trend(current, prior, before, tolerance)`** -> `"Stable"`, `"Decreasing-Stabilized"`, `"Decreasing-Not-Stabilized"`, `"Increasing"` or None. 12 files, **12 distinct bodies**, so each reads the guideline differently or the same guideline differently. Not built until `sonnet-packs` confirms one definition against the clause; it is the largest disagreement in the survey and a policy-adjacent choice, so the ranking puts it last for building and first for a decision.

Not worth an entry: `_dedupe` (`list(dict.fromkeys(...))`, 4 files), `_nonnegative` (4 files; `to_decimal` then `>= 0`), `_first_decimal` (10 files; `rules_lib.first` over `to_decimal`), `_policy_refs`, `_facts`, `_conditions`, `_worksheet`, `_metrics` (framework and finding construction, not computation).

## Float versus Decimal

The prompt's table offers `float(value)` for a DECIMAL column and its examples compare `float(ltv) < 80.0`, while 70 files use `Decimal(str(x))` and 14 use `float(`. A float percentage compared with a threshold gives different answers at the boundary than the exact decimal (`79.99999999999999` is below 80 only because of how it was divided); entries 1 and 2 return Decimal and int so the generator has one way to coerce. Zero denominators: 1 file of 115 catches `ZeroDivisionError`, and the prompt's DTI example divides raw `Decimal(str(debt)) / Decimal(str(income))`, which raises on a zero income. `rules_lib.ratio` returns None for a zero denominator and is the entry to point the generator at.

## Credit

All eight candidates are re-expressed in std's shape (a different signature, a declared unknown policy, and a different answer where the survey found the copies wrong), so the credit rule names no one in code. The one place a table could be carried over is the street-suffix and unit-designator list in `same_address`: write std's own list from the USPS abbreviations, and if the codec's list is copied, credit its author. The module history does not name one: `codec-core` entered kernel-lab in a single copy commit (`b83d88f29d`, 2026-10-08, committed as `rrahimi2025`), and the original author is in the `codec-suite` history, which was not read. Check it before copying any table.
