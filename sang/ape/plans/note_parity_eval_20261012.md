# Eval and feedback parity: japes vs eval-service

Date: 2026-10-12. Read-only. japes at `plato` `1b6972b6`; eval-service at `main` `fd1d250` (2026-10-09).
Paths: japes relative to `/Users/sangit/src/japes`, eval-service (ES) relative to `/Users/sangit/src/eval-service`.

## Verdict

japes is ahead on the evaluation *core* (immutable datasets, resumable runs, judge cache and spend
cap, regression gates, noise floor, path comparison, optimization ledger, feedback-to-guidance,
tenancy) and behind on everything that touches *live external entities*: asynchronous, long-running
invocations with webhook or poll completion, per-run isolation of the knowledge an entity reads and
writes, trace-derived scoring wired into the catalog, the depth of the comparison report, and the
runtime half of feedback (injection, hybrid retrieval, attribution analysis). ES moved fastest since
2026-08-01 exactly there (KH clone isolation, process comparison, tool/code custom scorers,
multi-turn input). ES never imported `jazzx_eval_contracts` (no hit in `app/` or `pyproject.toml`),
so contract convergence is one-sided.

## Gaps ranked by what blocks retiring ES

Each "absorb" note is consumer-neutral (no client or sibling names in japes code).

1. **Asynchronous, long-running entity runs.** ES: `orchestrator.py:handle_invocation_complete`, `handle_process_complete`, `_poll_process_until_terminal`, `backstop.py`, `webhooks.py`, `router.py:ingest_process_eval_event`, `TestCaseRunStatus` (timeout, cancelled, human_task_required). japes awaits each invocation in place (`experiments.py:ExperimentRunner._run_case`). Absorb: let an `Invoker` return a pending invocation handle; persist the case as `running` with a deadline; add `ExperimentRunner.complete_case(experiment_id, case_id, outcome)` that scores and, when the last case settles, finishes; a signed completion route in `server/eval_api.py`; an optional `poll(handle)` on the invoker driven by the existing reclaim job (`plato/jobs.py`) which also enforces deadlines; extend `CaseRunStatus` with `timeout`, `cancelled`, `awaiting_human`. Without this, process and slow-agent evals cannot move.
2. **External entity invokers with per-experiment variant overrides.** ES: `invokers.py:AgentInvoker`, `ProcessInvoker`, `ExperimentBase.agent_config_overrides` (prompt, model, temperature, tools). japes `AssistantInvoker.invoke` honours `config["scope"]` only. Absorb: a typed `ExperimentSpec.overrides` (prompt, model, temperature, tool allow-list) passed to the invoker and recorded in the snapshot; a data-configured remote invoker (endpoint, auth header source, input mapping, output path) registered in `EntityInvokers`, so a host plugs any platform agent or workflow without code.
3. **Run isolation fixtures.** ES: `kh/cloner.py`, `clone_preparation.py`, `clone_rules.py`, `hooks/` (pre/post fail-closed, reference remap), dataset `clone_prep_status`, runs waiting on prep (`orchestrator.py:ClonesStillPreparing`). japes: none. Absorb: a `CaseFixtureProvider` protocol (prepare a frozen snapshot per dataset version, clone per case, rewrite references in the case input, release), fixture status on `DatasetVersion`, `before_case`/`after_case` hooks on `ExperimentRunner` that fail the case closed; first provider over `fabric.rag` collections / `fabric.entities`. This is what makes evals of writing agents reproducible and safe.
4. **Trace-derived scoring wired end to end, plus judge presets.** ES: `scorers/__init__.py:_TRACE_SCORER_DEFS`, `primitives/llm_judge.py` presets, `primitives/cost.py`, `trace_fetcher.py`. japes classes exist but are unregistered (`custom_scorers.py:standard_scorers`) and Plato invocations carry no trace. Absorb: register `operational_scorers()`, `trajectory_scorers()`, `qa_scorers()` in `standard_scorers`; have invokers attach the `CanonicalTrace` (or have the runner fetch it by `trace_id` from the trace store) into `context["trace"]`; ship groundedness/relevance/safety/completeness/tool-call judges as named built-in rubrics over `LLMJudgeScorer`. Small, and templates migrating from ES name these.
5. **Comparison report depth.** ES `comparison.py` (pairing key, cohort, config diff + interpretation, coverage of input changes, metric distributions, paged drill-down, flip-rate noise, warnings) and `process_comparison.py` (outcome transitions, contract variables). Absorb into `experiment_comparison.py:compare_experiments`: optional `pairing_key` path, `analysis_mode`, a config diff of the two snapshots (`Experiment.config`, template) against declared expected paths with the same interpretation labels, input/expected change counts via `diff_case_sets`, distributions per metric, `offset/limit/outcome` on the cases list, flip-rate beside the score floor, and call `path_comparison.diff_definitions` from `ExperimentRunner.compare_paths` when both runs record a definition.
6. **Feedback at runtime.** ES config injection fields and `/similar` over conversation messages (combined mode), `is_static`, similar-actionable. japes `render_feedback_block` is never called. Absorb: a chat lifecycle grounding kind that retrieves the entity's approved feedback (`similar_feedback`) plus pinned items and renders them at a configured position; add `pinned`, `injection_position`, `template` to `FeedbackConfig`; a `combined` retrieval mode (rank fusion of lexical and semantic); index actionable items as their own documents.
