[DEFECT] jazzx_sdk/pipelines/jtbdset.py:111 :: steps-heading-drops-procedure -- import and export disagree on what counts as a step heading, and on export a one-step procedure loses its purpose, references and outcomes.
Trigger: a COMMON block `## Purpose\nX\n## Steps\n1. a\n2. b\n## Outcomes\n- **Pass**: ok`. On import, `title.startswith("step")` accepts "steps", so the result is `steps=["## Steps\n..."]` with no checks. On export, `_is_step` tests `step\b`, which does not match "steps". `_render` then treats the rule as "imported whole" and returns only the steps block, so purpose, outcomes and references are silently missing from the exported JTBD. The same happens with any single step heading that starts with "step" but is not followed by a word boundary, such as "Stepwise review".
IMPORTANCE: high -- this is silent content loss in the artifact handed to MACER. It is reachable through `export_jtbdset` for any base block with one step section and no validation block. The only callers are this module and tests/test_jtbdset.py, and nothing outside the repo uses it yet.
