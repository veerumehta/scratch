[DEFECT] plato/static/evaluation.html:505 :: blank-case-added-silently -- "Add case" sends empty textareas as `""` for both `input` and `expected`, and the server accepts that and stores a junk case.
Trigger: open a feedback record and click "Add case" without filling either textarea. `parsed("")` fails `JSON.parse` and returns `""`. `FeedbackToDataset.input` / `.expected` are typed `Any` and are required, but `""` still passes (`jazzx_sdk/server/feedback_api.py:154-155`). `add_feedback_case` then revises the dataset with an empty case, opening the next version. The page reports "Added as fb_…; the dataset is now vN." The case id is derived from the feedback id, and `add_feedback_case` returns the dataset unchanged when that id already exists (`jazzx_sdk/evaluation/feedback_learning.py:47-48`). So once the empty case exists, a corrected second add from the page does nothing. The only fix is a hand-edited `PUT …/cases`. Either the page or `FeedbackToDataset` should refuse a blank input or expected.
IMPORTANCE: medium -- reachable from the one UI that calls `…/to-dataset` wherever `WRITES_ALLOWED` is true (local posture, or any posture with `auth` wired). Nothing warns the operator, but the bad case shows up in the dataset's case table and can be fixed through the datasets API. Nothing outside this repo calls the page.
