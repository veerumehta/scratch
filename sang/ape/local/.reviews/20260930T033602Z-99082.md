Take a `run_agent` inside `recall_scope()` or `compression_scope()`, with enough tool outputs that the 50 KB budget elides N of them over T model calls:
- The store ends up holding N×T full copies. The text the budget was meant to keep out of the prompt now grows without bound in process memory.
- Each stub's bytes change on every call. The prompt prefix from the first elided output onward is new each turn, so the provider cache that `run_agent` stabilizes with `prompt_cache_key` (`run_kit.py:550`) misses on everything after it.
- The model is shown a different `read_reference` id for the same output on each turn.

`test_input_filter_parks_elided_output_in_the_reference_store` asserts `len(store) >= 1`, which hides the duplication. A fix is to key refs on the output's content, or have `elide_tool_outputs` look up existing refs through the store.
