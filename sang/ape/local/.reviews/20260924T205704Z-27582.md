These fixes introduce no new defects. What I checked:

- **Section rule ids.** The segmenter now groups planner sections by the same `_slug` that `rule_id` is built from (policy_jtbd.py:248 and :284). Section slugs contain only `[a-z0-9_]`, and ids join them with `.`, so two sections with different slugs can never produce the same id. Duplicate ids inside one section are still handled by the extractor's `seen` set.
- **Planner output shapes.** A leftover unit whose slug matches a planner section named like `UNASSIGNED_SECTION` joins that section. Names that slug to nothing, such as `""` and `"!!!"`, both become `"job"` and are merged into one section. With no sections at all, the segmenter returns `[]`.
- **Cited units.** In `_job`, `cited` falls back to `segment.parts`, and a section always has parts. So `RuleCandidate.documents` is never empty for a jobs candidate. Each unit's `documents` comes from its own `document`, which `clause_segments(..., document=name)` sets.
- **The `excerpt` change.** `excerpt` changed from a constructor field to a read-only property. I grepped japes, jaci, plato and policy-workbench for `RuleCandidate(... excerpt=)` and found no caller that passes it.
