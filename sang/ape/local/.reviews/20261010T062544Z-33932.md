[DEFECT] jazzx_sdk/agents/document/agent.py:294 :: figure-quote-check-unreachable -- The new comment says a figure "must appear in its own quote", but the literal page check runs first, so the quote is never compared with the value, and the `_grounded(value, quote)` condition never decides anything.
Trigger: markdown `"Appraised value: $500,000; prior sale $950,000"`, value `950000`, quote `"Appraised value: $500,000"`. Line 287 returns `"literal"` before the quote is looked at, so a figure whose own quote names a different number is still admitted. When `_quoted(quote, markdown)` holds, the quote's digits are a contiguous run of the page's digits. So any value `_grounded` finds in the quote, it also finds on the page, and the `"quote"` branch can never return for a value with digits. The new test `test_a_figure_found_in_its_quote_is_grounded_by_the_quote` asserts `"literal"` on both calls, so it shows the same thing. The real behaviour is "a figure not printed on the page is refused". Either the comment and test name should say that, or the quote check has to run before the literal check for values with digits.
IMPORTANCE: medium -- Every DocumentAgent extraction with `ground_by_quote` reaches this. Silently accepting a figure that appears elsewhere on the page is not new. What is new is the claim, which the next reader will rely on.
