[DEFECT] jazzx_sdk/evaluation/feedback_retrieval.py:140 :: naive-until-typeerror -- `min(query.until, now)` compares the caller's `until` with an aware `datetime.now(timezone.utc)`. Nothing in `FeedbackQuery` or `_feedback_query` makes `until` timezone-aware.
Trigger: `GET /feedback/aggregate?group_by=day&until=2026-09-25T00:00:00`. FastAPI parses the value as a naive datetime, and `min` raises `TypeError: can't compare offset-naive and offset-aware datetimes`, so the request returns 500. On `GET /feedback/export`, the `StreamingResponse` has already sent a 200 and, for CSV, the header line, before the generator raises. The caller gets a broken body instead of an error status. A consumer that does not check for an incomplete chunked transfer reads an empty export. Before this diff the naive value went straight into the SQL filter and did not raise. Normalizing with `as_utc` (already used in `feedback_db.py`) before the `min` fixes it.
IMPORTANCE: medium -- reached by both routes that call `iter_feedback` (`export` at `feedback_api.py:319`, and `aggregate` via `aggregate_feedback`) whenever the caller sends `until` without an offset. Plato mounts both. Aggregate fails loudly. Export returns a 200 with a truncated body. No other caller of `iter_feedback` exists in this repo.
