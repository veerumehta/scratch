[DEFECT] jazzx_sdk/llm/model_overlay_db.py:370 :: flex-carry-reads-in-force-state -- `_priced_flex` decides whether to keep flex by reading `MODEL_PRICING`, which is whatever is in force right now, not the shipped row. Once a model has flex, no overlay can switch it off, and replicas that started at different times end up with different flex states.
Trigger 1, flex cannot be switched off:
- `pricing_from_mapping` passes every key into `ModelPricing`, so `put_many` accepts a payload with `"flex": false`.
- Example: `{"input": .., "output": .., "flex": false}` for `gpt-6-sol`, meant to withdraw flex.
- It registers as `False or True`, so `flex_gpt-6-sol` keeps sending `service_tier=flex` and keeps being priced at the flex rate.

Trigger 2, replicas disagree:
- An overlay sets `"flex": true` on a model whose shipped row has no flex tier, then a later overlay corrects only the rates.
- A replica that applied the first overlay holds `flex=True` and carries it into the second.
- A replica that boots after the second overlay starts from the shipped row, gets `flex=False`, and prices `flex_` calls at standard.

The fix is to carry `flex` from the shipped data row (`MODEL_DATA["models"][...]["pricing"]`) when the payload has no `flex` key.
IMPORTANCE: medium -- only `apply_overlays` reaches this. Its callers are the Plato overlay router (`plato/api/model_overlay.py:157` and `:203`) and `OverlayRefresher.sweep`, which runs every `DEFAULT_REFRESH_SECONDS`. Only a deployment that writes a `flex` key in an overlay payload can hit it. The Plato models page never writes one, but the bulk `put_many` path accepts it. No caller outside japes was checked.
