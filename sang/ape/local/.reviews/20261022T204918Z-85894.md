[DEFECT] jazzx_sdk/agents/call_guard.py:45 :: deadline-not-worst-case -- The docstring says the default deadline is the retry policy's worst case, "so a call that is only queued (a flex wait) is never cut". The code doesn't guarantee that.
Two reachable ways a healthy call gets cut:
(a) `RateGate.wait` (`concurrency/rate_limit.py:213`) keeps looping while other callers' 429s push `GATE.hold` further out. Each hold can be up to the 900 s cap. A call that is only waiting on the gate can therefore queue past attempts x (cap + 600) during a 429 storm on a concurrent extraction.
(b) `_bounded` wraps the whole `runner.run`, which can take up to `max_turns=30` turns. Each turn's model call has its own retry budget, so a run with tools can need several times one call's worst case.
In both cases the call raises `TimeoutError`. `failure_code` classifies that as `FAILURE_ERROR`, so the segment is never retried in the transient pass and the run lands with that part failed.
IMPORTANCE: medium -- reaches every scope that sets `use_call_deadline`: policy extraction `_run`, `run_pipeline_case` and `resume_pipeline_case`, and the 4 plato routes (packs.py:707, 785, 839, 1638). It shows up as a failed segment or a 500, and run health warns, but the cause reads as a model timeout, not a self-inflicted cut.
